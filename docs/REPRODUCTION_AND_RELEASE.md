## 5. 첫 재현에서 발견한 문제와 수정

처음에는 21단계 커밋 `f7ee0876a1dad7a54742410e7f410e31a3ce89ae`를 새 폴더에 받아 확인했습니다. 그때 두 가지 문제를 발견했고 새 커밋 `732a580`에서 고쳤습니다.

| 문제 | 원인 | 수정 |
|---|---|---|
| 새 폴더에 `on-client/.env.example`이 없음 | 저장소 `.gitignore`의 `.env.*`가 이 견본까지 제외하고 있었음 | `.gitignore`에 `!.env.example` 예외를 넣고 견본(비밀 없음)을 저장소에 포함 |
| 21단계 설명서에 내 PC의 절대경로가 적혀 있음 | 설명서에 작업 폴더 경로를 그대로 적었음 | `<프로젝트 폴더>` 표기로 바꿈 |

`f7ee087`에서 한 확인(`npm run check`, 기본 실행 HTTP 200)은 최종 결과에 합치지 않았습니다. 수정 후 새 커밋 `732a580`을 **새 빈 폴더에 다시 받아 3~4장을 처음부터 다시 수행**했습니다.

## 6. 데이터 보존·백업·복원 계획과 제한

| 대상 | 어디에 있나 | 보존·백업 | 복원 | 제한 |
|---|---|---|---|---|
| 케셰브 코드·문서 | Git 저장소(GitHub, 공개) | 저장소 자체가 백업. 로컬 사본은 `git clone` 또는 `git bundle`로 보관 | 새 폴더에 `git clone` 후 `git checkout <40자리 커밋>` | 커밋하지 않은 변경은 보존되지 않음 |

## 8. 버전·지원 범위·누락·미해결 사항

- **버전**: 케셰브 학생판(시작 틀 0.2.11 기반), 재현한 코드 커밋 `732a580`. 상태는 **검증 중인 버전**입니다. 22단계 통과는 원문 검토 기준의 수료이며, 실제 운영 인증이나 v1.0 자동 인증이 아닙니다.
- **이 문서를 담은 커밋과의 차이**: 이 문서를 담은 커밋은 `732a580`의 바로 다음 커밋이며 문서 파일(이 문서와 `README.md`의 링크 한 줄)만 바뀝니다. `git diff --stat 732a580 HEAD`로 확인할 수 있습니다.
- **지원 범위**: Windows 11, Node.js 22~24(확인은 v24.21.0), 내장 브라우저. 다른 환경은 확인하지 않았습니다.
- **미완료·누락**:
  - 실제 접근 제어·XDR 시스템(SDP) 연결과 실제 로그인·기기·판정·기록 값
  - 앱 안 AI 연결 성공과 실제 사건 설명
  - 19단계의 실제 조치 집행과 결과 재조회(연동 시스템 집행기 연결이 준비되지 않음)

  - 제공 실행 도구 `tools\start-alekov.ps1`의 실행, Node 24.19.0 정확 버전
  - 메뉴의 Tab·Enter만으로의 전환, 필터·XDR 경보 여러 건
  - 자료실(1~12단계)의 백업·복원 절차 재실행
- **비밀값**: 이 문서와 저장소에는 키·토큰·비밀번호를 적지 않았습니다.
